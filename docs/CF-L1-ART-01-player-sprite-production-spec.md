# CF-L1-ART-01 — 玩家 Sprite Sheet 製作規格

本文件定義 P1／P2 最終美術的製作與驗收規則。此次交付僅為規格；最終圖像須另行核准製作。不得因美術調整玩法、碰撞、移動、武器或傷害。所有共用飛機視覺規則以 [Aircraft Visual Framework v0.1](CF-AIRCRAFT-VISUAL-FRAMEWORK-v0.1.md) 為準；本文件只定義玩家的格位與輸出細節。

## 1. 共用製作與輸出規格

| 項目 | 規格 |
|---|---|
| 母稿單格 | **256×256 px**，所有狀態完全一致 |
| 完整圖表 | **1024×512 px**；4 欄 × 2 列，共 8 格 |
| 成品格式 | RGBA PNG，透明背景；保留可編輯的高解析度母稿 |
| 排列 | 從左至右、由上至下；不得自動裁切、緊密打包、旋轉或改序 |
| 朝向 | 機頭朝畫面上方；俯視為主，飛行員主要呈現頭頂／後腦 |
| 光源 | 全表共用畫面右上主光，左下側較暗；P1／P2 一致 |
| 風格 | 大頭 Q 版貓、簡潔可讀的二戰螺旋槳戰機；細節以縮小後仍清楚為準 |
| 清潔輸出 | 不含文字、標籤、格線、外框、背景、海面投影或地面接觸陰影 |

機體本身的明暗與遮蔽可保留；**Drop Shadow 一律由引擎控制**。可另交附標籤的人工審閱圖，但不得覆蓋乾淨成品。

螺旋槳須有清楚的中央槳轂，以及克制、半透明的旋轉圓盤或弧形模糊；避免縮小後形成雜訊的逐片精細槳葉。旋轉效果不得超出安全區。

## 2. P1 製作規格

- 資產 ID：`player.p1`；預定成品路徑：`assets/players/p1/sheet.png`。
- 飛行員：橘色虎斑貓，大頭 Q 版比例；由頭頂／後方仍能辨識橘毛、虎斑與雙耳。優先保留耳形及頭形，避免依賴正面表情。
- 戰機：銀／灰色二戰風格戰鬥機，紅色重點配色、貓掌徽記；主力機輪廓厚實、圓潤。保留可讀的螺旋槳旋轉效果。
- Normal 為身份母版：八格維持同一機身、翼型、尾翼、座艙、紅色裝飾、徽記與貓咪特徵；只改變姿態及必要反應。
- 頭部不可遮蔽主要機翼或吞沒戰機輪廓；不要為表情將飛行員轉為正面肖像。

## 3. P2 製作規格

- 資產 ID：`player.p2`；預定成品路徑：`assets/players/p2/sheet.png`。
- 飛行員：以白色為主的乳牛花色貓，大頭 Q 版比例；**僅一隻黑耳**。依 CF-L1-ART-02 使用者選用的參考圖，製作約定為貓自身右耳（Normal 頂後視位於畫面右側），所有姿態維持同一解剖側，不可因翻轉素材而換邊。
- 戰機：Corsair 啟發的二戰風格，深海軍藍搭配奶油／象牙白重點配色，貓掌徽記；以鮮明海鷗翼及靈活輪廓區別 P1。
- 以象牙白色塊與右上受光面維持海面上的輪廓辨識；不可依賴背景底板、烘焙投影或外部發光特效。
- 八格固定翼型、配色位置、座艙、徽記與黑耳身份；保留可讀的螺旋槳效果。飛行員頭部比例與 P1 相近。

## 4. 最終 4×2 Frame Map

表內座標為零起算；像素原點為整張圖左上角。每個來源矩形均為 256×256 px。

| 格 | 狀態／manifest key | row, column | 像素原點 x, y | 製作要求 |
|---|---|---|---|---|
| 1 | Normal / `normal` | 0, 0 | 0, 0 | 中性水平飛行；機頭朝上，機翼平展，建立身份母版。 |
| 2 | Move Left / `left` | 0, 1 | 256, 0 | 向左滾轉 Roll Left；機頭仍朝上。用不對稱翼面可見度、透視縮短及受光變化表達，不能用 Yaw 或整機斜轉代替。 |
| 3 | Move Right / `right` | 0, 2 | 512, 0 | 向右滾轉 Roll Right；機頭仍朝上。幾何可對應左滾轉，但必須重新處理固定右上光源，不能直接水平鏡像左格。 |
| 4 | Move Up / `up` | 0, 3 | 768, 0 | 輕微低頭 Pitch Down；保留俯視與朝上航向，僅克制的透視變化。 |
| 5 | Move Down / `down` | 1, 0 | 0, 256 | 輕微抬頭 Pitch Up；可略增加上機身／座艙表面的可見度，仍清楚呈現俯視。 |
| 6 | Special / `special` | 1, 1 | 256, 256 | 專用技能反應姿態，可表達武器系統啟動或更有力的動態；維持機體身份。不得烘焙槍口火光、彈體、炸彈爆炸或外部 VFX；主要特效交由引擎。 |
| 7 | Hit / `hit` | 1, 2 | 512, 256 | 專用受擊姿態，輕微震動／形變；貓可壓耳、縮頭，或加入縮小後仍可讀的汗滴提示。不依賴臉部表情；紅閃與畫面震動交由引擎。 |
| 8 | Crash / `crash` | 1, 3 | 768, 256 | 初次墜機／失控關鍵姿態；可有局部損傷、少量煙霧或失控傾角，仍能辨識是哪架飛機。完整爆炸／碎片序列留待獨立 VFX／動畫。 |

每格是一個關鍵姿態，並非八格連續播放的動畫。左右滾轉的明暗隨翼面姿態改變，但光源方向不變；各格的徽記、配色及黑耳不可跟著鏡像換邊。

## 5. Anchor、Safe Area 與雙機尺度

- 共用 anchor：每格 **(128, 128) px**，normalized pivot **(0.5, 0.5)**，對應機身中央質量附近的固定參考點。
- 先在 Normal 母稿確立機體原點，其他姿態繞同一原點製作。不得逐格依可見像素外框重新置中；機翼縮短、受擊偏移與煙霧不得導致整機跳位。
- 安全區採每邊 **32 px（12.5%）** 透明留白，主體及半透明效果都收在每格 **[32, 224) × [32, 224)** 的中央 192×192 區域；翼尖、尾翼、槳影不碰格邊。
- Normal 建議整機可見高度約 **176–192 px**，最大翼展不超過 **192 px**。兩機採相近佔格比例，Normal 高度、最大翼展與頭部尺寸建議相差不超過 **10%**；這是本規格的初始審閱容差，不是碰撞尺寸。
- 同姿態比較 P1／P2 的尺度。Roll 引起的合理翼展縮短應保留，不能為填滿格子而單格放大；Crash 也必須維持同一尺度與 anchor。
- 圖表不得包含引擎投影；透明邊緣須無白底／黑底殘邊，半透明槳影與煙霧需檢查縮小後的合成品質。

## 6. 已核對的引擎現況與日後接入

已核對 `src/assets.js`、`src/render.js` 與 `tests/player-assets.test.cjs`：目前八種 key 與上述格序一致，使用中心 pivot；manifest 暫為 96×96 cell、`displayScale: 0.75`，所以繪製的整格大小為 **72×72 Canvas 邏輯像素**。缺圖、載入中或失敗時使用 Canvas fallback。

日後接入 256×256 成品時，應將兩機的視覺 manifest cell 同步改成 256×256，並以 **`displayScale: 0.28125`（72 / 256）** 維持現有 72×72 整格顯示尺寸。不要只替換 PNG：現有載入器只檢查圖片的最低尺寸，較大的圖片可能通過載入卻仍按 96×96 錯誤裁格。相關尺寸測試需於該接入任務同步更新。

72×72 是包含透明留白的整格；依本規格安全區，最大可見範圍約為 54×54 邏輯像素。碰撞幾何不由圖像佔格比例決定，不得跟著縮放。

目前 Special／Hit／Crash 各只有一格，即使條目含 fps 也不代表已有多格動畫；目前遊戲未提供持續的 Special／Hit 動畫計時。這些姿態可在之後的美術預覽中指定檢查，不以改動玩法來觸發驗收。本任務不修改 manifest 或程式。

## 7. Gameplay-size 測試與核准條件

最終圖稿完成後，先以 **72×72 邏輯像素整格**預覽兩機八種姿態，使用實際 Canvas 縮放與瀏覽器顯示尺寸；256×256 放大檢查僅用於邊緣／細節，不可取代遊戲尺寸驗收。

1. 在實際海面、島嶼／陸地、密集子彈與特效附近，以及雙人並排場景，各檢查兩機全部八格；使用遊戲引擎投影進行合成。
2. 交替 Normal 與各方向／反應格，確認原點穩定、無意外跳位，左右 Roll 在縮小後仍能看出差異，航向仍朝上。
3. 確認 P1／P2 可立即區分；P2 海軍藍不融入海面，單隻黑耳在可見角度下仍盡可能可讀。
4. 確認兩機高度、翼展、頭部尺度相近；頭部不壓過飛機輪廓，雙人同屏仍保留足夠的敵機與彈幕辨識空間。
5. 檢查右上光源跨機體、跨八格一致；無鏡像光源、投影烘焙、格邊裁切、透明殘邊或槳影雜訊。
6. 保存遊戲尺寸場景截圖與八格審閱圖，逐項記錄通過／需修正；先修正圖像輪廓、色塊及細節，再複查。不藉由調整碰撞或玩法掩蓋可讀性問題。

尚未生成最終美術，因此上述視覺驗收均為**待執行**。正式美術交付應包含兩張乾淨 PNG、可編輯母稿，以及獨立的審閱圖／驗收紀錄。
